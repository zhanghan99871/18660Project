## 1. Setup

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

All commands below run from the repository root with the virtual environment's
Python (`.venv/bin/python`, or `python` after `source .venv/bin/activate`).

**Precision.** The project runs in float64. JAX's float width must be chosen
before any JAX array exists, so every script starts with:

```python
from swarm.config import configure_jax
configure_jax("float64")      # first, before creating arrays
```

The L-BFGS-B path requires float64 (§6.4). On this project's CPU benchmark,
float32 was only about 1.25x faster, so float64 is used everywhere.

## 2. Configuration files

| File | Contents | Who edits it |
|---|---|---|
| `configs/base.yaml` | Static model constants (§10), loss weights λ (§5.3), evaluation thresholds | You, before any optimization |
| `configs/data.yaml` | Scenario generators, layout rules, every dataset split | You; changing it invalidates cached data |
| `configs/hand_tuned.yaml` | Logged hand-tuning trials (at most 20) | You, then re-run the protocol |
| `configs/frozen.yaml` | Selected hand-tuned rule and feature centerings μ_z | Generated by `experiments.hand_tuned`, never by hand |

Load them from Python:

```python
from swarm.config import load_sim_params, load_frozen
from swarm.datasets import load_data_config

sim = load_sim_params()                     # SimParams: frozen, hashable
sim_half_dt = load_sim_params(overrides={"simulation": {"dt": 0.025, "horizon": 800}})
cfg = load_data_config()
frozen = load_frozen()                      # dict: b_hand, hand_weights, mu_z_fi, mu_z_pi, ...
```

Loading is strict: unknown or missing keys raise errors, so typos can't pass
silently.

## 3. Datasets

Build every split once (about 15 s). The files are the common random numbers
shared by all optimizers:

```bash
python -m experiments.build_datasets
```

```bash
python -m experiments.preview_maps
```

`preview_maps` draws one map of every scenario type to
`results/figures/map_preview.png`.

| Split(s) | Use |
|---|---|
| `exp1_train` (16), `exp2_train` (32) | SAA training sets for Exp1 / Exp2 |
| `exp2_train_single_bottleneck` | H3: one bottleneck map, 32 initial states |
| `val_id` | Validation: hand-tuning, checkpoints, θ_U selection |
| `test_id`, `test_ood` (100 each) | Exp2 test sets |
| `test_scale_n{20,50,100}_{fixed_area,fixed_density}` (50 each) | Scale tests |
| `pi_train`, `pi_val`, `pi_test_id`, `pi_test_ood` | Exp2-PI (choose p when loading) |
| `exp3_train` / `exp3_val` / `exp3_test_interp` / `exp3_test_extrap` | Exp3 maps, each with 8 adaptation + 16 evaluation episodes |

Load a split and turn it into the JAX episode batch the simulator uses:

```python
from swarm.datasets import load_split
from swarm.model import episodes_from_batch, take

batch, meta = load_split("val_id", sim)     # raises StaleDatasetError if configs changed
episodes = episodes_from_batch(batch)        # fully informed (p = 1)
pi_eps = episodes_from_batch(batch, p=0.2)   # first n_I agents of each episode's order are informed
one = take(episodes, 0)                      # a single episode
meta["horizon"], meta["map_scenarios"][0]
```

`episodes_from_batch(batch, k_max=40)` re-pads obstacles to a common count, so
different splits with the same N and T share one compiled function.
`batch.role` marks Exp3 adaptation (0) and evaluation (1) episodes.

## 4. Running the simulator

### 4.1 The simulation spec

`SimSpec` holds everything static, and is passed to jit as a static argument:

```python
from swarm.controllers import ControllerSpec, MASKS
from swarm.model import SimSpec

spec = SimSpec(
    sim=sim,
    controller=ControllerSpec("adaptive", MASKS["full"]),  # "fixed" | "adaptive" | "time"
    hard=True,                 # hard neighbor masks; False = compact smoothstep (needs eta > 0)
    horizon=meta["horizon"],   # T; use the split's horizon (fixed-density sets are longer)
    clock_horizon=None,        # Time-25 clock; set to the full T during horizon continuation
    gamma_missing=0.0,         # goal-distance feature of uninformed agents (0 or 1)
    remat=True,                # jax.checkpoint on the step (default; 200x less gradient memory)
)
spec_soft = spec.replace(hard=False)
```

### 4.2 Controllers and the parameter vector θ

Optimizers work on a flat θ that holds only the active parameters:

| kind | θ layout | dim (full / 1 behavior off / 2 off) |
|---|---|---|
| `fixed` | `b[active]` | 5 / 4 / 3 |
| `adaptive` | `[A[active].ravel(), b[active]]`, A is 5×4 over z = [ρ, o, γ, κ] | 25 / 20 / 15 |
| `time` | same as adaptive, over ω(t) = [t/T, (t/T)², sin 2πt/T, cos 2πt/T] | 25 |

Behavior order everywhere: separation, alignment, cohesion, goal, obstacle.
Masks: `MASKS["full"]`, `["no_alignment"]`, `["no_cohesion"]`,
`["no_alignment_cohesion"]`. Masked behaviors have weight exactly 0.

```python
import jax.numpy as jnp
from swarm.controllers import (bounds, logits_from_weights, pack, unpack,
                               warm_start, weights_from_logits)

b = jnp.asarray(logits_from_weights([1.5, 1.0, 0.3, 0.7, 3.9], sim.controller.w_max))
theta0 = warm_start(b, spec.controller)          # (A = 0, b): the adaptive rule equals the fixed one
A, b_full = unpack(theta0, spec.controller)
lo, hi = bounds(spec.controller, sim)            # [-4, 4]^d for every optimizer
weights_from_logits(b, sim.controller.w_max)     # back to behavior weights
```

The adaptive controller needs the frozen feature centering μ_z: `mu_z_fi` for
fully informed training, `mu_z_pi` for partially informed. The fixed and time
controllers ignore it (pass `None`).

### 4.3 Losses, gradients and populations

```python
from swarm import rollout

mu_z = jnp.asarray(frozen["mu_z_fi"])
eta = sim.smoothing.fixed_soft_eta                         # soft model only; ignored when hard

value = rollout.loss(theta0, episodes, spec, 0.0, mu_z)               # SAA objective (+ λ_R ||A||²)
value, grad = rollout.loss_and_grad(theta0, episodes, spec_soft, eta, mu_z)
values = rollout.population_loss(jnp.stack([theta0, theta0]), episodes, spec, 0.0, mu_z)
terms = rollout.terms(theta0, episodes, spec, 0.0, mu_z)              # LossTerms: goal, time, collision, ...
```

`eta` is a dynamic argument: changing it between continuation stages does not
recompile. Changing `spec` (horizon, hard/soft, controller) does.

For optimizers, `bind` fixes everything except θ and works in NumPy:

```python
obj = rollout.bind(spec, episodes, 0.0, mu_z)
obj.f(np_theta)              # float
obj.f_pop(np_thetas)         # (P,) array, one compiled call
obj.f_and_grad(np_theta)     # (float, float64 array), for scipy L-BFGS-B
```

### 4.4 Trajectories

```python
tr = rollout.simulate(theta0, one, spec, 0.0, mu_z)
tr.x         # (T+1, N, 2) positions; also v, u, weights (T, N, 5), features (T, N, 4)
tr.dominant  # (T, N) index of the strongest weighted behavior
```

## 5. Evaluating a controller

Report results on the hard simulator:

```python
from swarm.metrics import evaluate, summarize

m = evaluate(theta0, episodes, spec, 0.0, mu_z)    # EpisodeMetrics, one entry per episode
summarize(m, spec)                                  # dict of aggregate numbers
```

| Field | Definition |
|---|---|
| `success` | arrival ≥ `success_threshold` (0.95) at T |
| `collision_free` | no agent, obstacle or wall contact on any swept step (raw geometry, no margin, tol 1e-9) |
| `pair_events` / `obstacle_events` / `wall_events` | new contacts; a contact lasting several steps counts once |
| `contact_steps` | contacts summed over steps (a duration measure) |
| `min_clearance` | smallest signed clearance over the episode |
| `deadlock` | fraction of agents outside the goal whose speed stayed below 0.05·v_max for the final 40 steps |
| `completion_step` / `completed` | first step at which arrival ≥ 0.95 holds for 20 steps; T if never (censored) |
| `arrival_informed` / `arrival_uninformed` | partially informed breakdown (NaN when undefined) |
| `arrival_curve(_uninformed)` | arrival fraction over time, (T+1,) |
| `loss` | task loss terms (same swept loss as training, without regularization) |
| `feature_mean`, `weight_mean` | mean local features and behavior weights |

The pre-declared primary metric (§8.3) is
`summarize(...)["success_and_collision_free"]`. Thresholds live under
`evaluation:` in `configs/base.yaml`.

## 7. Hand-tuned baseline and frozen quantities

```bash
python -m experiments.hand_tuned
```

The protocol (§8.2):
1. Evaluate each logged trial in `configs/hand_tuned.yaml` on `val_id`; at most 20 are allowed.
2. Keep the best success-and-collision-free rate, breaking ties by task loss.
3. Run the λ-balance check (§5.3).
4. Compute μ_z from the selected rule's rollouts on `exp2_train` (FI) and `pi_train` at p = 0.2 (PI).
5. Write `configs/frozen.yaml`.

Each run's trial table goes to `results/hand_tuned/<timestamp>/trials.csv`. Use
`--no-write` to evaluate trials without changing the frozen file.

To change the baseline, append trials (with a note on the reasoning) and re-run.
Re-running changes μ_z, so do it **before** any adaptive optimization.

Current state: 15 trials logged. The selected rule is `slow_approach` with
w = (1.5, 1.0, 0.3, 0.7, 3.9), which scores 0.53 success-and-collision-free and
0.81 success on `val_id`.

## 8. Benchmark

```bash
python -m experiments.benchmark --budget-minutes 15
```

It measures compile and run time of every objective path, c_grad, XLA's memory
estimate, and what fits into a per-run budget B_run (§8.5). Output:
`results/benchmark/<timestamp>/benchmark.json`.

Reference numbers on the development container (4 CPU cores, float64, M = 32,
N = 30, T = 400):

| Path | Time per call | Rollouts / s |
|---|---|---|
| loss (one θ, 32 episodes) | 0.83 s | 39 |
| CMA-ES generation, 13 × 32 rollouts | 6.5 s | 64 |
| value_and_grad (soft, checkpointed) | 2.4 s | 14 |
| evaluate 100 test episodes | 2.1 s | 47 |

From these: c_grad ≈ 2.9. At B_run = 15 min, a run gets about 138 CMA-ES
generations or 380 L-BFGS-B gradient calls. One Exp1 run (300 evaluations)
takes about 2.6 min. Exp3's offline solves (3×10⁵ rollouts) take about 1.3 h.
Re-run the benchmark on the machine you'll use for the experiments.

## 10. Model notes and deviations from the design document

Implemented as specified: dynamics (§3.1), perception with m = n + 1 (§3.2),
the five behaviors (§3.3), the shared weight map and controllers (§4.1–4.2),
partially informed observation (§4.5), swept losses (§5.2), and the SAA
objective with λ_R‖A‖² (§5.4).

Changed or decided during implementation:

1. **Tangential obstacle term (§3.3).** The doc sums a tangential term per
   obstacle. On walls built from overlapping circles, the neighboring circles'
   tangents point *through* the wall, and agents tunneled straight through
   bottlenecks. The tangent is now taken from the combined repulsion
   n_i = Σ_k push_k n̂_ik, giving f_o = n_i + k_t |n_i| tanh(c_t(t_i·q_i + b_t)) t_i.
   For an isolated obstacle this is identical to the doc's formula (tested).
2. **Bottleneck gap placement.** The gap is centered within ±1 of where the
   start→goal line crosses the wall. Gaps placed anywhere along the wall
   trapped the swarm, since agents sense only 1 unit around them (generator
   version 2).
3. **Boundary force.** A normal-only [d_s − d]₊ push from each wall, added to
   the obstacle force (it shares w_o).
4. **Metric definitions.** L0 is floored at 1. Deadlock means stalled for the
   final 40 steps outside the goal. Completion needs a 20-step dwell.
5. **Time-25 clock.** ω(t) uses `clock_horizon` (default T). Pass the full T
   during horizon continuation.
6. **Checkpointing on by default.** It only affects gradients: 26 MB instead of
   5.4 GB of temporary memory for 32 episodes, and faster.

Open points to decide before the optimization phase:

- **λ check.** The ratio check passes (26.7 < 100). The doc's other
  requirement, that safety terms dominate once a violation occurs, does not
  hold for the hand-tuned rule (0 of 15 contact episodes). With λ = 10, a few
  shallow contacts cost less than a slightly later arrival. If you raise
  λ_c, λ_o, λ_b, do it now, before any optimization, and then re-run
  `experiments.hand_tuned`.
- **Exp3 descriptor.** All Exp3 maps use N = 30, so log N is constant.
- **Remaining baseline contacts.** These are crowd pressure (separation
  pushing front agents into obstacles) and crevices between overlapping random
  obstacles. Context-dependent weights (the adaptive controller) target exactly
  this trade-off.
